IEC104 Master NCC Integration Server

FastAPI wrapper over an IEC 60870-5-104 master client stack. Connects to one or more IEC104 slaves, aggregates telemetry, exposes live streams via WebSocket, and provides REST endpoints for commands and GI.
IEC104 Master FastAPI REST + WebSocket Multi-slave Reconnect
This package is structured as: Library → Application → Server. The library wraps the IEC104 DLL (ctypes), the application manages multiple connections, and the server exposes external interfaces.
Context-only note: this is intended for NCC/master-side interaction with your test bed slaves, not a general IEC104 toolkit.
Runtime ports
FastAPI: 0.0.0.0:8100
IEC104 slaves: from config.json
What this application does
  • Runs a FastAPI server to expose IEC104 master capabilities.
  • Connects to multiple IEC104 slaves (from config.json).
  • Decodes incoming ASDUs (SP, DP, measured value short) into a normalized JSON map keyed by IOA.
  • Streams reported_data to WebSocket clients.
  • Provides REST endpoints to issue commands and trigger General Interrogation (GI).
  • Includes reconnect behavior with exponential backoff if a slave connection drops.

Notes on WebSocket behavior
  • On connect: server sends initial snapshot master_app.get_reported_data().
  • Then it polls once per second and sends if there is data.
  • Additionally, slave updates trigger broadcasts via the callback mechanism.

How config is used
  • Iec104MasterApplication.__init__ reads config.json and creates clients.
  • connect() starts each client and wires callbacks.
  • Reconnect logic is per-client (threaded exponential backoff).
Reported data model
The master maintains a consolidated map reported_data with this structure: 
{
  "<slave_id>": {
    "<ioa>": { "value": 1, "quality": 0, "timestamp": 1730000000000 },
    "...":  { "value": 0, "quality": 0, "timestamp": 1730000001234 }
  }
}
Type support in this implementation
Incoming information objects are decoded using handlers mapped by io_type:
  • 30 → SinglePointWithCP56Time2a
  • 31 → DoublePointWithCP56Time2a
  • 36 → MeasuredValueShortWithCP56Time2a
Startup flow
  1. Run Iec104Master.py to start FastAPI on 0.0.0.0:8100.
  2. Server constructs Iec104MasterApplication and loads config.json.
  3. One Iec104MasterClient is created per slave entry.
  4. On FastAPI lifespan start, master_app.connect() starts each client and performs a GI.
  5. Consumers connect to /reported_data to receive live values.
Update flow (telemetry)
  1. IEC104 slave sends ASDUs; client _asdu_received decodes elements.
  2. Client updates reported_data[ioa] and invokes external callback.
  3. Application aggregates per-slave data into _reported_data.
  4. Server callback schedules WS broadcast on the event loop.
  5. WebSocket clients receive JSON updates.
Command flow (NCC → slave)
  1. Caller invokes REST /command with slave_id, select, ioa, value.
  2. Server calls master_app.send_command.
  3. Client builds IEC104 SingleCommand and sends process command.
Note: The API uses select boolean to represent both select and execute flows via the IEC104 library call.
GI flow (refresh)
  1. Caller invokes /send_gi?host=<slave_id>.
  2. Application calls client.send_gi() which sends interrogation command.
  3. Incoming ASDU responses update reported_data and get pushed to subscribers.

Operational notes
  • Reconnect is triggered when the connection handler receives CS104_CONNECTION_CLOSED.
  • On successful connect, the client sends StartDT and immediately requests GI.
  • Commands are issued using CS104_Connection_sendProcessCommandEx with CS101_COT_ACTIVATION.
