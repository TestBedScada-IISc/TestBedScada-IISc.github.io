SLD Interaction Application

FastAPI UI + SVG renderer that consumes backend reported data via WebSocket and forwards UI commands via backend REST.
FastAPI UI Server Backend WS Consumer Backend REST Caller Excel-driven Mapping SVG Updates
Documentation for Sld_viewer.py and bundle files. This is scoped to this application and its dependency on the backend driver’s REST/WS APIs.
Context guardrail: this is not a generic toolkit. It assumes (1) a backend driver exposing /reported_data and /service, (2) Excel mapping, and (3) SVG element IDs aligned to SLD_Tag.
External dependencies
Backend WS: ws://localhost:8000/reported_data
Backend REST: http://localhost:8000/service
Meter WS: ws://localhost:8000/dataset
What this application does
  • Serves an SLD UI (template + SVG) from FastAPI.
  • Consumes backend report stream over WebSocket and updates the screen.
  • Maps backend values to icon href or measurement text.
  • Broadcasts incremental updates to all connected browser clients.
  • Accepts UI control actions and forwards them as backend “Command” service calls.
Runtime ports
  • UI server: 0.0.0.0:8010
  • Backend driver: localhost:8000
  • Meter dataset: 10.64.36.112:8000
SVG binding rule
SVG elements (icons and text nodes) are updated by SLD_Tag. The Excel mapping binds a backend DataAttribute to a particular SLD_Tag and type (Breaker/Measurement/Sld, etc).

  • CommandRequest: request payload for /api/send_command.
  • SLDUpdateServer: application container (FastAPI + mapping + WS bridging).

Mapping logic
  1. DataAttribute is the primary lookup key for incoming updates.
  2. SLD_Tag is the UI element id to update.
  3. SLD_Type decides status icon vs measurement vs SLD switch trigger.
  4. Precision formats measurement values.
  5. For commands, DataObject is converted ST → CO and stored for the UI tag.
Special case: meter tags
Meter updates arrive from a different WS source and use a “synthetic attribute tag”:
<meter_id> + CamelCase(<field_name>)
Example: meter_id=4, key voltage_ab → 4VoltageAb.
That synthetic key must exist in Excel DataAttribute for the value to appear in the UI.
value_mapping.json
Defines icon filename → raw value mapping for each SLD_Type. The app inverts this to raw value → icon filename.

Backend WS message (reported_data)
{
  "<IED>": {
    "<RCB_NAME>": {
      "<base_da>": {
        "...": "nested MMS-decoded structure"
      }
    }
  }
}
Nested values are flattened and matched against Excel DataAttribute keys.
UI update message (broadcast)
{
  "status": {
    "<SLD_Tag>": "/static/icons/<icon_file.svg>"
  },
  "measurements": {
    "<SLD_Tag>": "123.45"
  },
  "switch_sld": "<DrawingId>"
}
Meter dataset message
{
  "meter_id": 4,
  "values": {
    "voltage_ab": 110.2,
    "current_a": 12.3,
    "...": "..."
  }
}
The application converts each values key to CamelCase and prefixes with meter_id to find a matching Excel DataAttribute (e.g., 4VoltageAb, 4CurrentA).
Data flow: backend → UI
  1. Connect to backend WS: /reported_data.
  2. For each message, decode JSON and flatten nested structures.
  3. Match flattened keys to Excel DataAttribute.
  4. Translate values to icons or formatted measurements.
  5. Broadcast incremental updates over /ws/ui to the browser.
Control flow: UI → backend
  1. User clicks an SLD element (identified by SLD_Tag).
  2. Browser calls POST /api/send_command with CommandRequest.
  3. Server resolves SLD_Tag → DataObject and maps ST → CO.
  4. Appends suffix: $SBOw / $Oper / $Cancel.
  5. Server calls backend GET /service with service_call JSON.
SLD switching behavior
If an Excel entry has SLD_Type = Sld and its value becomes true, the server sets active_sld and emits switch_sld to clients. The UI then loads static/<active_sld>_drawing.svg (fallback to default if missing).
